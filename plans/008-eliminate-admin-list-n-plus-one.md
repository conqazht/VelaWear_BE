## Why

Admin list services page root entities and then map lazy to-one associations for every row. This produces N+1 queries for common pages. Precise entity graphs or explicit projections can fetch only required to-one data without making global mappings eager or breaking pageable counts.

## Current state and evidence

- `src/main/java/vn/conganh/commercial/feature/order/OrderServiceImpl.java:37-41` maps a pageable order result; `Order.java:34-36` keeps `user` lazy; `dto/OrderResponse.java:34-40` reads user data.
- `src/main/java/vn/conganh/commercial/feature/payment/PaymentServiceImpl.java:24-28` maps payment pages; `Payment.java:38-40` keeps `order` lazy; `dto/PaymentResponse.java:22-27` reads it.

- These repositories also support dynamic `Specification` plus `Pageable`, so any fetch strategy must preserve specifications and a valid count query.
