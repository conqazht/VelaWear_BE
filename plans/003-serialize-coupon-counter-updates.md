## Why

Checkout uses conditional atomic updates for `usedCount`, but admin coupon edits load and save the entire entity without a row lock or `@Version`. A concurrent admin save can overwrite a successful checkout counter increment, violating usage limits. Serializing admin mutation with the same database row removes the lost-update window without redesigning checkout.

## Current state and evidence

- `src/main/java/vn/conganh/commercial/feature/coupon/Coupon.java:48-52` stores `usageLimit` and `usedCount` on the same entity and has no `@Version`.
