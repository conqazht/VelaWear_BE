## Why

`AuthServiceImpl` coordinates credential/OAuth flows, users, audit, JWT claims, refresh sessions, rotation, and sensitive-change revocation. Token codec logic is cohesive and testable, but moving persistence/session orchestration would risk the atomic Redis and DB security invariants established by auth hardening.

## Current state and evidence

- `src/main/java/vn/conganh/commercial/feature/auth/AuthServiceImpl.java:133-309` implements public auth flows; `323-449` creates/parses access and refresh tokens; `452-524` handles sensitive account changes.
- `src/main/java/vn/conganh/commercial/feature/auth/CONTEXT.md:42-56` requires Redis refresh rotation/CAS to remain atomic.
- `src/main/java/vn/conganh/commercial/feature/refreshtoken/RefreshTokenSessionService.java` and its implementation own Redis session lifecycle; token claims and session records include security-version/JTI invariants.

- BE-010 supplies characterization tests for claim shape, rotation, revocation, cookies/controller results, and stable errors.

## Implementation steps

### 1. Freeze the extraction boundary

Use BE-010 tests to freeze two asymmetric contracts: access encode only; refresh encode/decode with subject, refresh token type, nonblank JTI, numeric `securityVersion`, issued/expiry times, and stable validation failures. Leave resource-server access decoding, account-version lookup/comparison, audit, and session persistence outside the codec.

**Verify**: run both blocks separately. The negative search exits 0 with no output, proving the codec has no stateful/HTTP dependency and no access-decoder path; the positive search must find the qualified refresh decoder.

### 2. Implement and unit-test `AuthTokenCodec`

Move access construction/encoding and refresh construction/encoding/decoding only. Refresh decode must reject wrong/missing type, blank/missing JTI, and missing/malformed `securityVersion` with existing stable errors. Inject the decoder explicitly with `@Qualifier("refreshJwtDecoder")`; do not add access decode or copy resource-server validation.

**Verify**: `.\mvnw.cmd --batch-mode --no-transfer-progress -Dtest=AuthTokenCodecTest test` → exit 0; access encoding and refresh encode/decode/type/JTI/`securityVersion` validation match fixtures, and no raw token is logged.

### 3. Delegate from auth orchestration

Replace private JWT implementation in `AuthServiceImpl` with codec calls. Preserve the exact order: validate request/user, create/update DB audit as established, create/rotate Redis session atomically, issue response, and handle rollback/failure consistently.

**Verify**: `.\mvnw.cmd --batch-mode --no-transfer-progress -Dtest=AuthServiceImplTest,AuthControllerTest test` → exit 0; public contracts and security-relevant collaborator order are unchanged.

### 4. Verify refresh and revocation races

Run refresh CAS, replay, concurrent rotation, logout, session-version mismatch, password/email reset, and Redis cleanup failure tests against the refactored code.

**Verify**: `.\mvnw.cmd --batch-mode --no-transfer-progress -Dtest=AuthRefreshConcurrencyIntegrationTest,RefreshTokenSessionServiceIntegrationTest,RedisSecurityAndCleanupIntegrationTest test` → exit 0; one refresh wins and revoked/session-version-mismatched tokens remain rejected.

### 5. Update documentation

Update auth `CONTEXT.md`, `docs/ARCHITECTURE.md`, and `docs/PROJECT-STATUS.md`; place the security-boundary notes only inside those exact allowlisted files to assign codec versus session/orchestration responsibilities.

**Verify**: `rg -n "AuthTokenCodec|resource-server|refresh|Redis|CAS" src/main/java/vn/conganh/commercial/feature/auth/CONTEXT.md docs/ARCHITECTURE.md docs/PROJECT-STATUS.md` → docs explicitly state access encode-only, refresh decode ownership, and the separate resource-server/session boundaries.
